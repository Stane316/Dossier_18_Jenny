# PHASE 2 — JENNY EXPERIENCE MAP & IDENTITY

**Document de référence — `Docs/02_JENNY_EXPERIENCE_MAP_IDENTITY.md`**
**Projet : Jenny — 18 ans & Bac**
**Version : 1.0**
**Statut : Phase 2 — livrable de conception**

---

# 00 — PURPOSE

Ce document transforme le contexte personnel fourni sur Jenny en un **système d'identité expérientielle exploitable par les phases suivantes**.

Il ne constitue pas encore le Design System visuel final.

Il ne définit pas encore :

* les écrans définitifs ;
* les composants ;
* les couleurs hexadécimales finales ;
* les animations ;
* la 3D ;
* l'architecture technique.

Il définit plutôt :

> **qui est Jenny dans l'expérience, ce que le site doit lui faire ressentir, quels éléments doivent permettre de reconnaître immédiatement son identité et comment cette identité doit guider la conception.**

Cette séparation est importante : le Design System générique indique que l'identité visuelle, la palette, le storytelling et la composition spécifique ne doivent pas être automatiquement réutilisés d'un projet à l'autre. 

---

# 01 — POSITIONNEMENT DE L'EXPÉRIENCE

Le site doit célébrer simultanément trois dimensions :

```text
                  JENNY
                    │
        ┌───────────┼───────────┐
        ↓           ↓           ↓
      18 ANS       BAC       RELATIONS
        │           │           │
        └───────────┴───────────┘
                    ↓
             EXPÉRIENCE JENNY
```

Le troisième axe est particulièrement important.

Le site ne doit pas seulement célébrer **un anniversaire et une réussite scolaire**.

Il doit montrer :

> **la place que Jenny occupe dans la vie des personnes qui ont choisi de lui laisser quelque chose.**

Cela transforme la collecte de messages, photos et vidéos en matière narrative.

---

# 02 — EXPERIENCE PROMISE

La promesse de travail du projet devient :

> **Créer pour Jenny une expérience numérique qu'elle ne pourrait raisonnablement confondre avec celle de quelqu'un d'autre.**

Le critère de réussite n'est donc pas simplement :

> « Le site est beau. »

Mais :

> **« Jenny reconnaît son univers avant même qu'on lui explique ce qu'elle regarde. »**

Et idéalement :

> **« Les personnes qui ont contribué reconnaissent également immédiatement que cette expérience a été construite pour Jenny. »**

# 04 — PERSONALITY CORE

## 04.1 — Attentionnée

Jenny est décrite comme une personne attentive aux autres.

Elle écoute réellement.

Elle ne se contente pas de réponses superficielles.

Elle cherche à comprendre.

### Traduction expérientielle

Le site doit avoir une dimension **humaine**, pas uniquement spectaculaire.

Le contenu des proches doit être traité comme quelque chose de précieux.

---

# 05 — FRANCHISE

Jenny est décrite comme :

* franche ;
* directe ;
* cash ;
* capable de dire lorsqu'une personne se trompe ;
* capable également d'encourager lorsqu'elle estime que la personne est dans le vrai.

Cela produit une caractéristique identitaire forte :

> **elle ne joue pas un rôle.**

### Traduction expérientielle

L'expérience ne doit donc pas avoir un ton excessivement artificiel ou sentimental.

Elle peut être tendre sans devenir mièvre.

Elle peut être élégante sans devenir froide.

Elle peut être drôle sans devenir enfantine.

---

# 06 — PRÉSENCE

Une caractéristique importante de la relation décrite est sa capacité à remarquer lorsqu'une personne ne va pas bien.

Elle peut détecter qu'il existe quelque chose derrière un :

> « Non, ça va. »

Cette capacité constitue une forme de **présence émotionnelle**.

### Traduction expérientielle

Le site doit privilégier les contenus authentiques :

```text
voix
visage
souvenir
anecdote
message personnel
vidéo
```

C'est une raison supplémentaire pour laquelle la vidéo devient centrale.

---

# 07 — LE RÔLE DE « PSY »

La relation contient également une dimension particulière :

> Jenny s'est parfois considérée comme la « psy » de Stane.

Ce détail ne doit pas nécessairement être affiché littéralement dans l'interface.

Mais il constitue un élément important du modèle relationnel :

```text
écoute
↓
confiance
↓
conseil
↓
présence
↓
soutien
```

C'est un exemple de **micro-détail identitaire** qui peut éventuellement être exploité dans le storytelling ou dans une contribution personnelle.

---

# 08 — EMOTIONAL PROFILE

Le profil émotionnel décrit est nuancé.

Jenny :

* exprime ses émotions ;
* peut pleurer lorsqu'elle est très triste ;
* peut également pleurer lorsqu'elle est en colère ;
* lorsqu'elle est très en colère, elle préfère parfois se retirer pour éviter de dire quelque chose qu'elle regretterait ;
* ne semble donc pas simplement « cacher » ce qu'elle ressent.

Il faut donc éviter une représentation trop simplifiée du type :

```text
Jenny = joyeuse
```

Le modèle doit plutôt être :

```text
JOY
+
TENDERNESS
+
FRANKNESS
+
INTENSITY
+
VULNERABILITY
+
HUMOR
+
STRENGTH
```

## 🐱 CHATONS — PRIORITÉ 01

Correction essentielle apportée par l'utilisateur :

> **Jenny aime les chatons encore davantage que les lapins.**

Cette information devient donc une règle du projet.

### Statut

**PRIMARY PERSONAL SYMBOL**

Les chatons peuvent représenter :

* tendresse ;
* affection ;
* douceur ;
* côté attendrissant ;
* élément personnel immédiatement reconnaissable.

Mais il faut éviter une utilisation infantilisante.

# 15 — BLACK AS DEPTH

---

# 16 — ROSE : EXCLUSION RULE

Le rose ne doit pas constituer une couleur de marque ou d'identité.

Cela ne signifie pas qu'un média envoyé par un proche ne pourrait jamais contenir accidentellement du rose.

La règle est :

> **ne pas choisir volontairement le rose comme langage visuel principal de l'expérience.**

---

# 17 — CINEMATIC TASTE

Jenny aime les films d'horreur.

Cela ouvre une possibilité de langage visuel :

* tension ;
* obscurité ;
* révélation ;
* ombre ;
* silence ;
* contraste ;
* anticipation.

Mais :

> **le site n'est pas un site d'horreur.**

L'horreur est une **référence esthétique potentielle**, pas l'identité globale.

# 18 — INVESTIGATION / POLICE

Jenny aime les films d'enquête policière.

Cette préférence est particulièrement intéressante parce qu'elle peut devenir une **mécanique d'expérience**.

Une enquête implique :

```text
INDICE
↓
CURIOSITÉ
↓
RECHERCHE
↓
DÉCOUVERTE
↓
RÉVÉLATION
```

Cette structure correspond très bien à une expérience interactive.

Elle pourra donc potentiellement influencer :

* les transitions ;
* les indices ;
* la navigation ;
* les chapitres ;
* les objets ;
* les messages cachés.

# 19 — ROMANCE

Jenny aime la romance, particulièrement dans les animés.

La romance constitue le contrepoids à l'esthétique sombre.

Elle apporte :

```text
TENDERNESS
+
WARMTH
+
RELATIONSHIP
+
EMOTION
```

Le système final devra donc éviter d'être uniquement :

```text
dark
mysterious
horror
```

Il doit également être :

```text
warm
human
intimate
romantic
```

sans transformer l'expérience en déclaration romantique de la part de l'auteur.

L'objectif est de célébrer **une amie**, à travers son réseau de proches.

# 27 — PERSONALIZATION LAYERS

La personnalisation doit fonctionner à plusieurs niveaux.

### Niveau 1 — Global

### Niveau 3 — Interaction

### Niveau 4 — Narrative

### Niveau 5 — Micro-details

Les petits éléments confirment son identité.

# 28 — MICRO-DETAILS

C'est probablement ici que l'expérience peut devenir réellement exceptionnelle.

Exemples potentiels :


> **découverts, pas affichés comme une liste de caractéristiques.**

---

# 29 — IDENTITY RECOGNITION TEST

Une future version devra être évaluée avec une question simple :

> **Si on remplace le nom « Jenny » par celui d'une autre personne, l'expérience semble-t-elle toujours fonctionner ?**

Si la réponse est oui :

**personnalisation insuffisante.**

Si la réponse est :

> « Non, certains éléments fondamentaux n'auraient plus de sens. »

alors l'identité est suffisamment intégrée.

---

# 30 — CONTRIBUTOR RECOGNITION TEST

Deuxième test :

> **Une personne qui connaît Jenny peut-elle reconnaître que le site est pour elle avant même de lire son nom ?**

Cela devient un objectif de design.

# 31 — CONTENT STRATEGY

Les contributions peuvent être classées conceptuellement en trois types :

```text
MESSAGE
PHOTO
VIDEO
```

Mais leur valeur expérientielle peut être différente.

### MESSAGE

Intimité, pensée, souvenir, encouragement.

### PHOTO

Preuve visuelle d'un moment partagé.

### VIDEO

Présence humaine, voix, expressions, personnalité.

---

# 32 — VIDEO EXPERIENCE

Les vidéos devront être pensées comme des **moments de présence**.

Une vidéo ne doit pas simplement être affichée dans :

```text
<video>
```

puis terminée.

Elle peut être introduite par :

```text
PERSON
↓
CONTEXT
↓
ANTICIPATION
↓
VIDEO
↓
REACTION
↓
MEMORY
```

Cette approche devra être approfondie en Phase 3 et Phase 6.

# 33 — CONTRIBUTION EXPERIENCE VS JENNY EXPERIENCE

Le système doit explicitement distinguer les deux.

## Contributeur

Objectif :

> **envoyer quelque chose rapidement et simplement.**

Donc :

```text
EFFICIENT
CLEAR
LOW FRICTION
```

## Jenny

Objectif :

> **explorer, découvrir et ressentir.**

Donc :

```text
DISCOVERY
IMMERSION
EMOTION
NARRATIVE
```

Cette distinction correspond directement au principe UX distinguant les expériences orientées tâche et les expériences orientées découverte.

# 36 — DISCOVERY MODEL

La découverte peut être organisée en trois degrés :

### Visible

Ce que Jenny comprend immédiatement.

### Discoverable

Ce qu'elle peut trouver en explorant.

### Hidden

Les easter eggs et détails réservés à l'exploration.

```text
VISIBLE
   ↓
DISCOVERABLE
   ↓
HIDDEN
```

Cette hiérarchie permettra de créer de la profondeur sans rendre l'expérience confuse.

# 40 — MOTION PERSONALITY

La personnalité de Jenny peut également influencer le motion design.

### Mystère

Révélation progressive.

### Enquête

Déplacement / connexion / focus.

### Romance

Mouvements fluides et doux.

Suspension / tension / apparition contrôlée.

Mouvements plus ouverts et lumineux.

---

# 41 — 3D PERSONALITY

Si une scène 3D est retenue plus tard, elle devra répondre à :

```text
Que représente-t-elle pour Jenny ?
```

et non :

> « Quelle scène 3D pouvons-nous faire ? »

La 3D pourra servir :

* identité ;
* profondeur ;
* narration ;
* découverte ;
* interaction ;
* transition.

Le système recommande précisément de ne pas utiliser la 3D comme démonstration technologique indépendante du contenu. 

---

# 42 — AUDIO PERSONALITY

L'audio pourrait potentiellement renforcer :

* immersion ;
* vidéos ;
* ambiance ;
* transitions.

Mais il ne doit jamais être imposé.

Le système UX exige notamment un contrôle clair du son et la possibilité de le désactiver.

# 44 — EXPERIENCE CHARACTER

Si l'expérience était une personne, elle devrait donner une impression :

> **mystérieuse au premier regard, chaleureuse lorsqu'on s'en approche, surprenante lorsqu'on l'explore et profondément humaine lorsqu'on découvre les contenus.**

Cette phrase constitue une synthèse importante de la direction.

---

# 45 — DESIGN PRINCIPLES FOR JENNY

## JDP-01 — Jenny before trend

Aucune tendance visuelle ne doit être adoptée si elle ne correspond pas à Jenny.

## JDP-02 — Contrast creates identity

Les contrastes font partie de son identité.

## JDP-03 — Personal details create authenticity

Les petits détails ont plus de valeur que l'accumulation d'effets.

## JDP-04 — Human media matters

Les vidéos et messages doivent conserver leur authenticité.

## JDP-05 — Mystery should invite, not confuse

La découverte doit susciter la curiosité.

## JDP-06 — Darkness needs warmth

L'univers sombre doit être contrebalancé par de la tendresse.

## JDP-07 — Celebration must remain visible

L'expérience ne doit pas devenir tellement artistique qu'on oublie :

```text
18 ANS
+
BAC
```

## JDP-08 — Immersion must preserve control

L'expérience doit rester contrôlable et accessible.
